# 地图导出 —— 赛道中心线（惯导用）

> 由 `文档/赛道图-5000x5000-黑底白线.png`（原件，已在仓库里）自动提取。
> 生成脚本：`脚本/赛道图转惯导地图.py`（只用 numpy + PIL）。重跑：`python 脚本/赛道图转惯导地图.py`

| 文件 | 说明 |
|---|---|
| `赛道中心线-预览.png` | 提取结果叠在原件上（红线=中心线，绿短线=方向，蓝方块=发车点）——**先看这张核验** |
| `赛道中心线-mm.json` | 10mm 等弧长路点，含 s / x / y / yaw / R（全精度，3710 点） |

## 关键数

| 项 | 值 | 怎么来的 |
|---|---|---|
| 比例 | **5.8005 mm/px** | 场地外框 862px = 5000mm；E 区 R300 圆（109px 外径=625mm）交叉验证 |
| 单圈周长 | **37.11 m** | 沿中心线累计（闭环） |
| **s=0** | **发车点** | S-G 两线之间的净空中点（S 线中心 x≈2546mm、G 线 x≈2998mm，净空 400mm），即 (2772, 203) mm |
| **行进方向** | **车头朝 S ⇒ 顶直线沿 −X** | 由用户给定（发车点在 S-G 之间、车头朝 S）；s 递增即真实跑向 |
| 自检 | 最大单步跳变 **98.6mm**（限 100）✓ ；E 区之外骨架覆盖 **100%** ✓ | 脚本每次重跑自动打印 |

## 坐标系

```
原点 = 场地左上角；X 向右；Y 向下（与赛道图同向）
yaw  = 0° 指向 +X，顺时针为正
R    = 曲率半径 mm（直线填 1e9）
s    = 沿中心线的累计弧长 mm，从发车点起算，方向 = 真实跑向
```
若用 Y 向上/逆时针为正的右手系：`y` 取负、`yaw` 取负。

## ★E 区（4 个相切圆）—— 地图与实物线不一样，这是故意的

实物/原图在 E 区画的是 **4 个完整的外切圆**（R300）。但车**不能绕整圆**（会死循环），
正确过法是**在每个相切点换圆**，于是实际路线是一条蛇形（每个圆只走半边）：

```
进 E（自 D 区）→ 第4圆右半 → 第3圆左半 → 第2圆右半 → 第1圆左半 → 出 E（第1圆顶点，向上）
```

所以地图在 E 区**只覆盖每个圆的一半**——另半边是"车不走的分支"，覆盖率统计里已把 E 区排除
（全区 630 个未覆盖点全部在 E 区，属设计预期）。

⚠ **固件侧要注意**：实物是完整圆 ⇒ 每个相切点物理上是"四臂交汇"，**纯灰度质心解不出来**
（两条分支几何对称）。必须靠**里程/航向**做显式切换（框架里规划的 `ring.c` 状态机就是干这个的）。

## 限制

- 从 CAD 截图自动提取；弯道中心线有 ±2~3mm 抖动（像素+细化固有），别当毫米级基准。
- 实跑要用十字/斑马线**地标重置**吸收赛道铺装误差。
- 脚本每次重跑都会打印两条自检（最大跳变 ≤100mm、E 区外覆盖 100%）；**改完务必看预览图**。

## 重生成

```bash
python 脚本/赛道图转惯导地图.py <赛道图.png> <输出目录>
```
换赛道：改脚本里的 `FIELD_PX`（外框像素范围）与 `START_X_MM/START_Y_MM`（发车点）。
