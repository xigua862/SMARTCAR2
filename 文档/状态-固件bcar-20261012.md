## 四、串口命令（115200 8N1，PB6=TX / PB7=RX）

| 命令 | 作用 |
|---|---|
| `HELP` | 命令列表 |
| `PING` | 应答 `PONG`（测链路）|
| `STATUS` | 状态/节拍/电机/按键/蜂鸣器/MAPR |
| `MAPR` | 打印 AFIO->MAPR（查重映射）|
| `HELLO 0\|1` | 关/开每秒心跳（调参时关掉免得刷屏）|
| `BEEP [ms]` | 蜂鸣 |
| `MODE <IDLE\|TEST\|RUN\|ESTOP>` | 切模式（切的时候强制刹车）|
| `MOTOR <FWD\|REV\|BRAKE\|COAST> <0~1000>` | 两侧同设 |
| `MOTOR L\|R <dir> <mag>` | 只设一侧 |
| `KEY` | 读两个按键电平 |
| `LOOPBACK [ms]` | TX-RX 短接时的回环自检 |

## 五、★施工中发现的 4 个真问题（都已绕开/修掉）

1. **Windows 不区分大小写**：`drivers/` 与 CubeMX 的 `Drivers/`（HAL）是同一个目录 ⇒ 自写源码统一放 **`bcar/src/`**，否则 CubeMX 重新生成时会把我们写的驱动删掉。**框架文档 §1.2 的目录树按此修正。**
2. **CubeMX 命令行不肯生成"USART1 走 PB6/PB7 重映射"**（`IP not ready`）⇒ USART1 完全手写（寄存器 + 重映射 + 环形缓冲）。副产物：AFIO 重映射、MOE 这类"错了就很难查"的点全在明面上。
3. **中文源码必须补 UTF-8 BOM**：中文 Windows 下 ARMCC 按 GBK 解析 UTF-8 源码 → 一堆 `#870-D` warning，破坏"0 warning"判据。已写 `Tools\fix_bom.py`（二进制里存的仍是 UTF-8，串口终端显示中文正常 ✓ 已验证）。
4. **命令解析 bug（被单测抓到）**：`MOTOR FWD 500` 曾经永远解析失败 —— 先截断了命令词，后面参数就取不到了；三参数的 `MOTOR L FWD 500` 又因为拿整串去比 `"L"` 而失败。现在解析抽成纯模块 `str_util.c` 并配 78 条单测，**改完就跑，不用上板**。
