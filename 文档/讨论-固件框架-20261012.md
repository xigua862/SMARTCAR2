> 触发：《`开场提示词-军师-固件框架-20261012.md`》。

> 规矩：本文任何数字都要标【手册】/【实测】/【算术】/【猜的】/【待实测】；没标的一律当"猜的"处理。
> 术语第一次出现附大白话：**φ=直径**；**R=半径**（R200 就是半径 200mm 的弯）；**M3 配 φ3.2 过孔**=M3 螺丝要穿过去得打 3.2mm 孔；**轴距**=同侧前后轮中心的距离；**轮距**=左右轮中心的距离；**LAP=每圈遥测行**；**P95=按大小排后 95% 分位那个值**；**CRC=循环冗余校验，一串哈希，用来判数据有没有坏**；**乒乓备份=两份交替写，永远保留一份好的**；**MOE=Main Output Enable，TIM1 高级定时器的主输出总开关，忘了开就是"程序在跑电机不转"**；**DRDY=Data Ready，IMU 采完一次数据就拉一下的引脚**；**ODR=Output Data Rate，IMU 每秒输出多少次数据**。

## 0. 一句话结论（先看这个）

- **工程名 `bcar`**（Keil MDK 工程文件 `bcar.uvprojx`，产物 `bcar.hex`）——**绝不叫 test16**（A 车 Keil 工程就叫 test16，历史上已撞过一次）。工程目录建议放 **`c:\Users\asus\Desktop\test16\bcar\`**（与废弃的 `固件-STM32空壳\` 并列，互不干扰）。
- **分层**：`bsp/` 板级（寄存器）→ `drivers/` 外设 → `middleware/` 算法（**无硬件依赖，可 PC 单测**）→ `control/` 控制环 → `app/` 决策+通信。**依赖严格单向，不许反调**。
- **调度**：**主循环 + SysTick 5ms 置标志**（不在 ISR 里跑业务，避免雪崩）；急停走 **EXTI 优先级 0** 直切 MOE。5ms 拍内部时序预算 **<340µs**，占空 6.8%，**留 4.66ms 余量**（【算术】见 §3.3）。
- **参数存哪**：**C8T6 无 EEPROM**【手册：ST 官方 datasheet】，用 **Flash 末页（0x0800FC00~0x0800FFFF，1KB）乒乓双备份 + CRC32**。擦写寿命 10k 次【手册：datasheet 表 6】，乒乓策略下 **=1000 万次 SET**【算术】，够用一辈子。
- **四大卡点全部给解**（§5.4 / §6.2 / §7 阶段 8 三处交叉覆盖）：① 三层读回校验 + 上电 loopback 自检；② LAP 13 字段（对齐 v1.9 §4）+ **P² 分位近似**（20KB RAM 装不下全量排序，见 §6.3）；③ `PARAM_AUTORUN` 默认 **0** + PB0 测试模式（motor 滑行休眠、纯串口）；④ ESTOP 走 EXTI 直断 MOE + `param_rollback()` 影子备份。
- **风格**：寄存器 + HAL 混用——**初始化用 HAL**（省事、CubeMX 生成的能直接用）；**热路径用寄存器**（`TIM1->CCR1 = x`、`SPI2->DR`、`ADC1->SR` 这类，避免 HAL 层函数调用开销）。
- **分 9 阶段落地**（§7），每阶段有硬判据；**任一阶段不过关，不进下一阶段**——这是"防返工"的最便宜手段。
- **军师本轮到此为止**：不建工程、不写 `.c/.h/.uvprojx`。等用户对 §9「待你拍板」5 条点头，再派工人卡。

**硬纪律**：
1. `middleware/` 不许 `#include "drivers/xxx.h"`——只能吃 drivers 输出的数据结构（通过 control 或 app 层传参）。这样在 PC 上就能跑单元测试（**对齐调参迭代器的 sim 后端**）。
2. `drivers/` 不许 `#include "middleware/xxx.h"` 或 `#include "app/xxx.h"`——底层不知道上层存在。
3. **ISR 里禁止调 `middleware/` 或 `control/` 里的任何非纯函数**（避免 ISR 时长失控）。

## 2. 模块划分与职责（谁干什么、不干什么、依赖谁）

### 2.1 bsp/ 板级底层（**寄存器级**）

| 文件 | 干什么 | 不干什么 | 依赖 |
|---|---|---|---|
| `bsp_clock` | HSE 8MHz + PLL ×9 → 72MHz【手册：C8T6 datasheet】；APB1=36MHz / APB2=72MHz；外设时钟使能（`RCC->APB2ENR` / `APB1ENR`） | 不管外设具体行为 | HAL RCC |
| `bsp_gpio` | GPIO 模式/上下拉/速度批量配置。**PA0~PA7 = 模拟输入**（ADC）；**PA8~PA11 = 复用推挽 50MHz**（TIM1 PWM）；**PB6 = 复用推挽 / PB7 = 浮空输入**（USART1 重映射）；**PC13/PB0 = 上拉输入**（按键）；**PC14/PC15/PA12 = 推挽输出 2MHz**（LED） | 不管引脚功能定义（那在 drivers 里） | 寄存器 `GPIOx_CRL/CRH` |
| **`bsp_afio`** ★ | **① 禁 JTAG 保 SWD**（`AFIO->MAPR` 的 `SWJ_CFG=010`）→ 释放 PA15/PB3/PB4；**② TIM2 部分重映射**（CH1→PA15, CH2→PB3）；**③ TIM3 部分重映射**（CH1→PB4, CH2→PB5）；**④ USART1 重映射**（TX→PB6, RX→PB7） | 别的一律不管 | 寄存器 `AFIO->MAPR` |
| `bsp_systick` | SysTick 5ms 中断（200Hz）；**DWT->CYCCNT** 微秒计时（IMU dt 用，72MHz 下 1µs = 72 count） | 不做业务调度 | Cortex-M3 SysTick + DWT |
| `bsp_nvic` | 中断优先级分组 = **4 位抢占（NVIC_PRIORITYGROUP_4）**；各外设中断使能（见 §3.1 优先级表） | — | HAL NVIC |
| `bsp_flash` | Flash 末页（**0x0800FC00~0x0800FFFF，1KB**）擦写；半字（2B）编程；CRC32 软件实现（多项式 0xEDB88320） | 不做参数解析 | HAL FLASH |

⚠ **bsp_afio 必须在任何用到 PA15/PB3/PB4/PB6/PB7 的外设初始化之前调用**——否则：
- 忘禁 JTAG → PA15/PB3/PB4 是 JTAG 功能，**两个编码器全没读数**（框架定稿 §2.3 软件坑 1）；
- 忘 USART1 重映射 → TX 走 PA9（能用），RX 走 PA10（悬空）→ **正是"能发不能收"的经典症状**（框架定稿 §2.3 软件坑 3，也是交接3 §0.6 悬案的一个可能原因）。

### 2.2 drivers/ 外设驱动

| 文件 | 干什么 | 不干什么 | 依赖 | 关键约束 |
|---|---|---|---|---|
| `motor.c` | AT8236 双通道 PWM。接口 `motor_write(u_speed, u_steer)` → 差速混合 → `TIM1->CCR1..4`。方向映射：正转 = `IN1=PWM, IN2=LOW`；反转 = `IN1=LOW, IN2=PWM`；**刹车 = `IN1=HIGH, IN2=HIGH`（真值表 `11`）**；**滑行 = `IN1=LOW, IN2=LOW`（真值表 `00`）** | 不做速度环、不做保护逻辑 | TIM1（HAL 初始化 + 寄存器 CCR 更新）+ `bsp_afio` | ★**控制环里"停"必须用 `11` 刹车，禁用 `00` 滑行**——`00` 持续 >1ms 进休眠，唤醒需 ~1ms【手册：AT8236 datasheet 真值表 + 休眠行为】；5ms 周期里占 20%，会让减速/找线动作发糊。<br>★**TIM1 必须开 MOE**（`__HAL_TIM_MOE_ENABLE(&htim1)`）——忘了就是"程序在跑、电机不转"【手册：STM32F1 参考手册 §14.3.9】。<br>★**最小占空 >4.4%**（消隐 2.2µs @20kHz）【手册：AT8236 datasheet】→ 固件里 `mag` 下限设 50/1000。<br>★**侧框架翻转后 `PARAM_MOTOR_DIR_FLIP = 1`**（两个电机一起翻，编码器"一侧取负"不用变）【框架定稿 §1.2 表末】。 |
| `encoder.c` | TIM2/TIM3 硬件正交计数（4× 模式）。接口 `encoder_sample()` 返回 `{left_cnt, right_cnt, left_delta, right_delta, t_ms, hz_left, hz_right}`；**右侧取负号**（框架定稿 §1.3）| 不算里程（那是 `middleware/odom`） | TIM2/TIM3（寄存器 `CNT`）+ `bsp_afio` | ★**TIM 编码器接口不开中断**——由 SysTick 每 5ms 读一次 CNT snapshot【框架定稿 §3】。<br>★**PA15/PB3/PB4 是 JTAG 脚复用**——必须先禁 JTAG（见 bsp_afio）。<br>⚠ **计数率 >200kHz 要换方案**【框架定稿 §1.3】——k=4.4 时 1.2m/s 就 299kHz【算术】。阶段 3 验收判据里已卡。 |

## 3. 任务与调度

### 3.1 时基与中断优先级（**NVIC 优先级分组 = 4 位抢占**）

| 中断/任务 | 频率 | 抢占优先级（0 最高）| 干什么 | 阻塞风险 |
|---|---|---|---|---|
| **EXTI0 (PC13 长按)** / **EXTI15_10 (nFAULT)** | 事件驱动 | **0** ★最高 | 急停：直切 motor_brake + 断 MOE + 蜂鸣 + LED | 无（就几行寄存器操作） |
| **SysTick** | **200Hz（5ms）** ★控制拍 | **1** | 只做 `tick_ms += 5` + `flag_control_5ms = 1`；**不跑业务** | 无（<1µs） |
| **EXTI9_5 (PB8 IMU DRDY)** | 由 IMU ODR 决定（建议 200~1660Hz） | 2 | 采样 gyro Z 一次，写入 `imu_sample`；给 heading 积分提供 dt | ⚠ 若 ODR 过高（>2kHz）会挤压 SysTick；用 IMU 内部 ODR 配到 200~1000Hz |
| **DMA1_CH1 (ADC1)** | 循环模式，转换完成即搬 | 3 | 8 通道扫描搬到 `ir_raw[8]`，**无 CPU 中断**（循环模式）| 无 |
| **USART1_RXNE** | 事件驱动 | 4 | 单字节进环形缓冲（128B），主循环里 `getline` 拿 | 无（<2µs/字节） |
| **DMA1_CH4 (USART1_TX)** | 事件驱动 | 5 | TC 中断里清 busy 标志 | 无 |
| **TIM2/TIM3 编码器** | 硬件计数，**不开中断** | — | 由 SysTick 每 5ms 读一次 CNT snapshot | — |
| **TIM1_UP** | 20kHz PWM 载波 | — | 硬件产生 PWM，**不开中断** | — |
| **主循环 `while(1)`** | 空闲 | — | `Task_Control_5ms()` + 按键扫描 + 串口命令解析 + 状态机跳转 + LAP 打印 + 故障记录写 Flash | 允许阻塞（不影响控制拍——SysTick 会抢占它） |

**优先级设计原则**（结论先行）：
- **急停 > 控制拍 > IMU DRDY > ADC DMA > 串口 RX > 串口 TX**
- SysTick 抢占一切（优先级 1，仅次于急停）；
- 主循环是"后台"，被 SysTick 抢占完全 OK；
- **绝不允许任何 ISR 阻塞超过 100µs**——否则 5ms 拍会被拖崩。

### 3.2 ★为什么 SysTick ISR 里不直接跑 Task_Control_5ms

**结论：SysTick ISR 只做 `tick_ms += 5` + `flag_control_5ms = 1`；业务在主循环里跑。**

三条理由（每条都能翻车）：
1. **ISR 里执行会屏蔽同级或更低优先级中断**——USART1_RXNE（优先级 4）会被屏蔽；如果 Task_Control_5ms 里 `uart_printf` 用了 HAL 阻塞版（禁用！），RX 会掉字节。
2. **若 Task_Control_5ms 意外超时（>5ms）**，下一次 SysTick 直接叠上来 → **系统雪崩**（栈溢出、状态机错乱）。
3. **主循环模式下超时会"跳一拍"**（可观测、可告警——`tick_ms` 会跳 10 而不是 5），**比雪崩好**。

**主循环骨架**（`main.c`，只是**接口示意**，本轮不落文件）：
```c
int main(void) {
    bsp_clock_init();  bsp_afio_init();  bsp_gpio_init();
    bsp_systick_init();  bsp_nvic_init();  bsp_flash_init();
    drivers_init_all();                 /* motor/encoder/adc_ir/imu/uart/buzzer/key/led */
    param_load();                        /* Flash → RAM，CRC 坏则 load_defaults */
    selftest_run_all();                  /* 5s 内跑完；任一失败 → fsm_event(EV_FAULT) */
    fsm_init();                          /* 根据 param.autorun 决定进 IDLE 还是 COUNTDOWN */
    while (1) {
        if (flag_control_5ms) {
            flag_control_5ms = 0;
            Task_Control_5ms();          /* 全部业务在这，预算 <2ms */
        }
        Task_Background();               /* 按键、串口命令、状态机跳转、Flash 写、LAP 打印 */
    }
}
```

**唯一例外**：`estop` 走 EXTI（优先级 0），ISR 里直接切 motor 到刹车 + 断 MOE，**不等主循环**。

### 3.3 Task_Control_5ms 内部时序预算（**总 ≤2ms，留 3ms 余量**）

**结论先行**：预算总 **<340µs**，占空 **6.8%**，留 **4.66ms 余量**给意外——**5ms 周期稳，甚至能压到 2ms（500Hz）**（如果日后要提速）。

| # | 步骤 | 预算 | 怎么算的 |
|---|---|---|---|
| 1 | `encoder_sample()`（读 2×TIMx_CNT） | <10µs | 寄存器直读，2×32bit = 8 cycles @72MHz ≈ 0.11µs；加函数调用开销 ≈5µs【算术】 |
| 2 | `adc_ir_sample()`（DMA 已备好，memcpy 16B） | <5µs | memcpy 16B ≈8 cycles ≈0.11µs；加开销【算术】 |
| 3 | `imu_sample()`（SPI2 已备好，或从 DRDY ISR 缓存取） | <20µs | 3 字节 SPI @9MHz = 24 bit / 9MHz = 2.67µs；加开销【算术】 |
| 4 | `line_pos_compute()`（8 路归一化 + 加权） | <50µs | 8 次浮点乘除 + 8 次加 = ~40 FLOPs；Cortex-M3 FPU=软件模拟，每 FLOP ~20 cycles → 800 cycles ≈11µs；加数组访问开销 ≈30µs【算术，M3 无 FPU 是硬事实】 |
| 5 | `odom_update()`（差速积分） | <30µs | 2 次三角函数（可用小角度近似 `sin(x)≈x`, `cos(x)≈1-x²/2`）；~20 FLOPs【算术】 |
| 6 | `heading_update()`（gyro 积分 + 零偏补偿） | <20µs | 1 次乘加 = 2 FLOPs【算术】 |
| 7 | `ins_corr_update()`（PD + 门限） | <30µs | 若 `corr_on=0` 直接跳过；开启时 ~10 FLOPs【算术】 |
| 8 | `speed_pid + angle_pd + gyro_damp` | <80µs | 三个二阶环节，共 ~30 FLOPs【算术】 |
| 9 | `slowsafe + profile`（查表 + 限幅） | <50µs | `nav_path` 表 96 段，二分查找 ~7 次比较；R 表可预计算【算术】 |
| 10 | `mixer + motor_write`（差速混合 + CCR 更新） | <10µs | 寄存器直写 4×CCR ≈20 cycles【算术】 |
| 11 | `telemetry_sample`（累加 Welford + P² 环形缓冲） | <30µs | 每拍 O(1)【算术】 |
| **合计** | — | **<340µs** | 占空 6.8%，**留 4.66ms 余量** |

⚠ **M3 无 FPU 是硬事实**【手册：ARM Cortex-M3 技术参考手册】——所有浮点都是软件模拟（每次乘除 ~20 cycles）。**若阶段 3~7 实测超预算，第一优化项 = 把 `middleware/` 里的 float 换成 int32_t 定点**（Q16.16 格式，误差 <0.001%）。

### 3.4 哪里会阻塞（**必须点名，全部有对策**）

| 位置 | 阻塞时长 | 出处 | 怎么办 |
|---|---|---|---|
| **Flash 页擦除**（1KB）| **20~40ms** | 【手册：STM32F1 参考手册 §3.3.4 表 5】 | ⚠ **绝对禁止在 Task_Control_5ms 里擦 Flash**；只能在主循环里、且**车必须停着**（`fsm.state ∈ {IDLE, TEST_MODE, ESTOP}`）；擦除期间 SysTick 照常触发但 motor 强制刹车 |
| **Flash 半字编程**（2B）| ~50µs / 次 | 【手册：STM32F1 参考手册 §3.3.5】 | 参数写 ~40 半字 × 50µs = 2ms → **拆到多个主循环 tick 里做**，或**只在车停时批量写** |
| `uart_printf`（TX DMA）| **非阻塞** ✓ | 本项目设计 | DMA 发送，CPU 立刻返回；只等 busy 标志（下一次发送前判断） |
| `uart_getline`（命令行）| 允许阻塞 | 本项目设计 | 只在主循环里、且带超时（默认 100ms） |
| `selftest_run_all()` | ~5s | 本项目设计 | 只在 BOOT 阶段跑，motor 强制刹车 |
| **IMU SPI 读**（3~6B） | ~10µs @9MHz | 【算术】 | 允许在 Task_Control_5ms 里 |
| **AT8236 休眠唤醒** | **~1ms** | 【手册：AT8236 datasheet 真值表】 | ⚠ **控制环里禁止用 `IN1=IN2=0`**（滑行+休眠），必须用 `11`（刹车）→ 见 motor.c 硬约束 |
| **ADC 单次转换** | ~1µs × 8 通道 = 8µs | 【手册：STM32F1 参考手册 §11.6】 | DMA 循环模式，CPU 不参与 ✓ |
| **nFAULT EXTI ISR** | <10µs | 本项目设计 | 优先级 0，抢占一切，但 ISR 体积极小 |
| **蜂鸣器长鸣** | 阻塞？不阻塞 | — | `buzzer_beep(ms)` 非阻塞（用 tick），主循环里轮询是否到时 |

### 5.2 参数存哪（**Flash 末页方案，不用 EEPROM**）

**为什么不用 EEPROM？**
- STM32F103C8T6 **没有 EEPROM**【手册：ST 官方 datasheet】——这是硬事实。
- 常见替代：① 外挂 I2C EEPROM（AT24C02）；② 用内部 Flash 末页模拟。
- 我们的板子**没有外挂 EEPROM**（引脚图 §2.3 全车只剩 PB11 一个空脚，接不了 I2C 总线）。
- ⇒ **用 Flash 末页模拟**（业界标准做法，ST 官方应用笔记 AN2594 就是这个方案）。

**Flash 布局**（C8T6 = 64KB Flash，128 页 × 1KB【手册：datasheet 表 4】）：
```
0x08000000 ~ 0x0800F7FF   固件代码（62KB，够用；开 -O2 后预计 30~40KB）
0x0800F800 ~ 0x0800FBFF   faultlog 区（1KB，故障记录）
0x0800FC00 ~ 0x0800FFFF   ★param 区（1KB，最后一页）
                             ├─ 0x0800FC00: 主备份 A（512B）
                             └─ 0x0800FE00: 副备份 B（512B）
```

**参数块结构**（`param_blob_t` 序列化后 ~160B，见 §4.4）：
- `magic` (2B) + `version` (2B) + `v[PARAM__COUNT]` (~128B) + `crc32` (4B) + `write_count` (4B) + `reserved` (16B) = **~160B**
- 两个备份共 320B < 512B ✓

**擦写策略（乒乓）**：
1. **每次 `param_commit()` 只写一个备份**：读两份的 `write_count`，选**计数小的那份**写；写完 `write_count = 另一份 + 1`。
2. **写入前**先算好整块的 CRC32，写入后再**回读一次**重算 CRC，匹配才返回 OK。
3. **上电加载**：读 A、读 B，都算 CRC；**选 write_count 大且 CRC 对的那份**；若两份都坏 → `param_load_defaults()` + 蜂鸣三声报警。
4. **页擦除只在必要时做**：当选中要写的那份所在的 512B 区已经有旧数据（不是全 0xFF）时，才擦整页 1KB；擦完两份都清零，再写。
5. Flash 页擦除 endurance = **10k 次**【手册：datasheet 表 6】→ 乒乓策略下 **=10k × 2 = 2 万次 COMMIT**；若每天调参 100 次，够用 **200 天**【算术】。若担心不够，可以扩到"每份 128B，一页 8 份轮转"→ **8 万次 COMMIT**（本轮不做，留退路）。

### 5.3 怎么改（三条路径）

| 路径 | 谁用 | 生效时机 | 落 Flash？ |
|---|---|---|---|
| ① **串口 `SET <键> <值>`** | 调参迭代器 / 上位机 | 立刻（写 RAM） | ⚠ **不落**（除非追加 `COMMIT`）|
| ② **串口 `COMMIT`** | 用户手动 | — | ✓ 落 Flash（乒乓备份）|
| ③ **代码里改默认值 `param_defaults[]`** | 军师/工人 | 下次烧录后 Flash 空/CRC 坏时生效 | 编译期落 |

⇒ **调参器每次改动 = 一串 SET + 一次 COMMIT**（可选）；如果只做单次实验，可以只 SET 不 COMMIT，重启自动回上次 COMMIT 的值。

⇒ **RUN 前打快照**（`param_snapshot_last_good()`）：进 `FSM_COUNTDOWN` 时把 RAM 里的当前参数拷进"影子备份"（RAM 中的 `param_shadow` 结构体，不落 Flash）；调参器判失败发 `ROLLBACK` 时，`param_rollback()` 把影子拷回主 RAM。**这样"参数回退"不需要动 Flash**（避免 20~40ms 擦除阻塞），也避免磨损。

### 5.4 ★怎么读回校验（**卡点 ①：串口"能发不能收"悬案的解**）

**三层校验**（每层都能独立发现"值写歪了 / 线断了 / Flash 位翻了"）：

**第 1 层：写入即回读（RAM）**
```
SET kp_angle 1.234
→ 固件：param_set(PARAM_KP_ANGLE, 1.234) 写 RAM
→ 固件：读回 param.v[PARAM_KP_ANGLE]，sprintf("%.8g", v)
→ 回：OK 1.234
调参器侧：assert 回读值 == 写入值（相对误差 ≤1e-3，对齐 使用手册-调参迭代器 §3.3）
```
**为什么这样能治"能发不能收"**：调参器发一条 SET，若固件回了 `OK 1.234`，就同时证明了 TX（板→PC）和 RX（PC→板）都通。若只回 `OK` 不带值（旧设计），只能证明 TX 通，不能证明 RX 通。**回读值 = 一次 SET 顺带把 RX 也验了**。

**第 2 层：GET 命令（RAM）**
```
GET kp_angle     → OK 1.234
GET ALL          → OK {"kp_angle":1.234,"kd_angle":0.5,...,"crc32":"0xABCD1234"}
```

**第 3 层：COMMIT 后 CRC 校验（Flash）**
```
COMMIT
→ 固件：擦 Flash 备份页（若需要）→ 写 param_blob_t → 读回 → 算 CRC32
→ 若 CRC 匹配：回 OK
→ 若不匹配：回 ERR CRC，并保留 RAM 值（用户可重试）

VERIFY
→ 固件：从 Flash 主副备份都读一次，比对 CRC
→ 回 OK <crc_A> <crc_B> <write_count_A> <write_count_B>
→ 若任一坏：回 ERR CRC_A 或 ERR CRC_B
```

**★"能发不能收"悬案的板级 + 固件级双重防护**（对齐 交接3 §0.6）：

**板级已做**（交接3 §0.6，硬件已定，不再讨论）：
- ① RX（PB7）**不加电容**，可加 10k 上拉到 3.3V；
- ② 丝印写清 `TX→接对方RX` / `RX←接对方TX`；
- ③ **只用一根 USB**（DAPLink VCP，SWD + 串口合在 6P 座）——从根上消除地环。

**固件级要做的**（本框架新增）：
1. **RX 中断必须开**：`__HAL_UART_ENABLE_IT(&huart1, UART_IT_RXNE)` + `HAL_NVIC_EnableIRQ(USART1_IRQn)`（框架定稿 §2.3 坑 3 隐含要求）；
2. **RX 脚（PB7）必须配成"浮空输入"或"上拉输入"**，**绝不能是 AF_PP**（这是"能发不能收"最常见原因之一，虽然用户已排除，但每次 CubeMX 重新生成时都要复核）【手册：STM32F1 参考手册 §9.1.9 表 19】；
3. **USART1 必须重映射到 PB6/PB7**（`AFIO->MAPR` 的 `USART1_REMAP` 位置 1）——若忘了，TX 走 PA9（能用）、RX 走 PA10（悬空，永远收不到）→ **正是"能发不能收"的经典症状**（框架定稿 §2.3 坑 3 明列）；
4. **★上电自检加一条 `selftest_uart_loopback()`**：让固件自己发一个字节 `0xA5`，然后**等 100ms 看 RX 环形缓冲里有没有收到**。**若 DAPLink 的 VCP 支持回环**（多数支持，比如 Black Magic Probe / CMSIS-DAP 都支持），这一步就能证明 TX 和 RX 都通。**收不到 → 蜂鸣三声 + LED 闪烁 + 打印 `ERR UART_RX` + 打印 `MAPR` 与 `GPIOB_CRL` 值**——工人一看就知道是重映射没设还是 RX 模式错；
5. **上电打印一次引脚配置**：`INFO MAPR=0x%08X` `INFO GPIOB_CRL=0x%08X` `INFO GPIOB_CRH=0x%08X`——一旦悬案复发，一行日志就能定位是"重映射没设"还是"RX 模式错"。

**期望的 MAPR 值**（【算术】按 STM32F1 参考手册 §9.4.2 表 62 位定义算）：
```
SWJ_CFG[26:24] = 010 (禁 JTAG 保 SWD)     → bit26..24 = 0b010 → 0x02000000
TIM3_REMAP[11:10] = 10 (部分重映射 PB4/PB5) → bit11..10 = 0b10  → 0x00000800
TIM2_REMAP[9:8] = 01 (部分重映射 PA15/PB3)  → bit9..8 = 0b01    → 0x00000100
USART1_REMAP[2] = 1 (重映射 PB6/PB7)         → bit2 = 1          → 0x00000004
合计期望：MAPR = 0x02000904
```
上电打印若与期望不符 → 立刻能定位是哪个位没设。

### 6.3 P95 分位怎么算（**内存受限下的近似**）

**为什么不能存全量排序？**
- 一圈 ~8s / 5ms = **1600 拍**；
- 4 个统计量（线 P95、惯导 P95，各一份）× 1600 × 4B = **25.6KB**；
- **C8T6 只有 20KB RAM**【手册：datasheet】——**装不下**。

**方案 A：P² 分位近似算法**（Jain & Chlamtac, CACM 1985）★**推荐**
- 每字段只用 **5 个 float + 5 个 int32 + 1 float + 1 uint32 = 44B**；
- 精度：±2%【手册：原论文】——对 P95 判据完全够用（v1.9 的 `p95_gate_mm` 门限本身也是整数级）；
- 每拍 **O(1)** 更新（5 次比较 + 5 次插值）；
- 已在开源社区广泛使用（Postgres、Redis 的 t-digest 前身）。

**方案 B：环形缓冲 256 拍（1.28s 窗）+ 排序**
- 内存 256×4 = **1KB/字段** × 2 = 2KB（可以）；
- **但只算最近 1.28s，不是整圈** → 语义不对（调参器要的是整圈 P95）；
- ❌ **不推荐**。

**方案 C：直方图近似**
- 分 32 个 bin，每拍落一个 bin，LAP 结束时累积到 95% 那个 bin 的中心值；
- 内存 32×4 = 128B/字段；
- 精度：±(bin_width/2) = ±3%（若量程 0~50mm）；
- ⚠ 可用，但 P² 更精确、更省内存。

**结论**：**用 P² 方案 A**，理由是"整圈"统计更符合调参器的语义，且内存只用 44B/字段。

- **前置条件**：本框架的 §4.4 param.c + §6.1 协议 + §6.2 LAP **必须先落地**（即 §7 阶段 8 完成）；
- **⚠ 键名对齐**：调参器冻结原型用旧仿真键名（`kp_steer`），本框架用 v1.8 键名（`kp_angle`）——**固件里程碑启动时派生工人卡：把原型 port 到对齐键名**【待并入 v1.9 §8】。

**档 3：实时示波（可选，调试用）**
- 追加二进制协议（`STREAM <字段列表> <频率>`）→ 每拍发一帧二进制；
- 上位机 Python + matplotlib 实时画；
- **本轮不做**（PCB 阶段用不上，日后需要再加）。

### 6.5 调试辅助（**不占 LAP 通道**）

- **`STAT` 命令**：任何时候敲，返回当前状态快照（JSON），不阻塞控制拍；
- **`DUMP` 命令**：全参数 + 传感器 raw + 最近 16 拍的 `line_pos.err_mm` 与 `odom.v_mm_s`（环形缓冲）；
- **三色 LED 状态映射**（阶段 8 定型）：
  - `PC14`（红）= **FAULT / ESTOP**：常亮 = 故障；快闪 = 急停
  - `PC15`（黄）= **RUN / COUNTDOWN**：常亮 = 跑；慢闪 = 读秒
  - `PA12`（绿）= **IDLE / TEST_MODE**：常亮 = 待机；慢闪 = 测试模式
- **蜂鸣器**（有源，只能开/关）：
  - 上电成功：短鸣 1 声
  - 自检失败：鸣 3 声（间隔 200ms）
  - 读秒：3-2-1 各短鸣 1 声，GO 长鸣 500ms
  - LAP 完成：短鸣 1 声
  - 急停：长鸣 3s（之后间歇，避免拉低 5V 轨）

### 阶段 2：电机开环（PWM 直控，不看反馈）

**做**：
- `drivers/motor.c`（TIM1 四路 PWM，20kHz，**开 MOE**）；
- 串口命令：`MOTOR <dir> <mag>` → dir ∈ {FWD, REV, BRAKE, COAST}，mag ∈ [0, 1000]；
- **硬约束**：`COAST` 只允许在**测试模式**下用（因为会进休眠）；`RUN` 状态下"停"一律用 `BRAKE`。

**验收判据**：
- ☐ `MOTOR FWD 500` → **两个电机同向转**（侧框架翻转后 = 车"前进"方向；若反了 → 改 `PARAM_MOTOR_DIR_FLIP = 1`，两电机一起翻）；
- ☐ `MOTOR REV 500` → 反向；
- ☐ `MOTOR BRAKE 0` → 两轮硬锁（用手拧不动，AT8236 真值表 `11`）；
- ☐ `MOTOR COAST 0` → 两轮自由（用手能拧）+ **1ms 后再 FWD 能立刻响应**（示波器看 IN1 上升沿到 OUT 有输出的延时 ≤1.5ms，验证 AT8236 休眠唤醒时间）；
- ☐ **占空比 ≤4.4% 时电机不转**（AT8236 消隐 2.2µs @20kHz = 4.4%【手册】）→ 固件里把 mag 下限设成 50/1000；
- ☐ **摸 AT8236 芯片**：跑 30s @ mag=800 不烫手（<60°C，用手背贴 3s 能忍）；
- ☐ **nFAULT 上拉**：正常跑时 nFAULT 引脚 = 高电平；短接电机两端模拟堆转 → nFAULT 拉低 → 固件报 `INFO nFAULT LOW`。

**没过就是**：MOE 忘开（程序在跑、电机不转）/ AT8236 IN1/IN2 接反 / R_ISEN 阻值错 / VM 供电不足。

### 阶段 8：param.c + telemetry.c + LAP 日志（**卡点 ②③④ 全落地**）

**做**：
- `app/param.c`（Flash 末页 + 乒乓备份 + CRC32）；
- `app/telemetry.c`（LAP 结算 + P² 分位）；
- `app/estop.c`（急停：长按 PC13 or nFAULT or 软件命令）；
- **AUTORUN=n 默认值**：`PARAM_AUTORUN` 默认 **0**（不自跑），只有用户显式 SET 或按 PC13 才进 RUN；
- **测试模式（PB0）**：进 `FSM_TEST_MODE`，motor 滑行休眠，纯串口取数；
- 全套串口命令（§6.1）。

**验收判据**（卡点逐一对应）：

**★卡点 ①（参数读回）**：
- ☐ `SET kp_angle 1.234` → `GET kp_angle` 回 `OK 1.234`（相对误差 ≤1e-3，对齐 使用手册 §3.3）；
- ☐ **COMMIT 后掉电保存**：`SET` + `COMMIT` + `RESET` → 重启后 `GET kp_angle` 仍是 1.234；
- ☐ **CRC 校验**：用 SWD 手动改 Flash 一个字节 → 上电 selftest 报 `ERR CRC`，自动 `param_load_defaults()` + 蜂鸣三声；
- ☐ **白名单**：`SET motor_dir_flip 1` → `ERR KEY`（非白名单键拒写）；
- ☐ **VERIFY**：回 `OK <crc_A> <crc_B> <wc_A> <wc_B>`，两份 CRC 都对。

**★卡点 ②（LAP 日志）**：
- ☐ `RUN 3` → 串口打出 **3 行** `LAP,<圈号>,...`，**13 字段一个不少**，格式对齐 v1.9 §4；
- ☐ **调参迭代器接得上**：`python 脚本/调参/调参迭代.py --port COMx --phase A --laps 3` 能拿到 LAP 并出诊断；
- ☐ **字段内容合理**：`线P95 > 线RMS`（否则 P² 算错了）；`惯导P95 > 惯导RMS`；`里程` 与单圈预期 12~18m 同量级；
- ☐ **结束原因**：跑到一半按 `STOP` → LAP 行的结束原因 = `ABORT`（不是 `OK`）。

**★卡点 ③（AUTORUN=n）**：
- ☐ **AUTORUN=0 默认**：上电 → 自检 → **进 FSM_IDLE，motor 刹车，不跑**；按 PC13 才进 COUNTDOWN → RUN；
- ☐ **AUTORUN=n>0**：SET + COMMIT 后重启 → 自检 → 直接进 COUNTDOWN → RUN → 跑 n 圈 → 回 IDLE；
- ☐ **测试模式 PB0**：按 PB0 → motor `IN1=IN2=0`（滑行休眠）→ 串口纯 SET/GET/DUMP，**不采集传感器用于控制**；
- ☐ **自检不过不自跑**：故意把灰度遮住（黑/白不可分）→ selftest 报 `ERR IR` + 蜂鸣三声 → **不进 autorun**（即使 `PARAM_AUTORUN = 3`）。

**★卡点 ④（急停 + 参数回退）**：
- ☐ **软件急停**：串口 `ESTOP` → motor 立刻刹车 + TIM1 MOE 断 + 蜂鸣长鸣 + LED 全亮 + 进 FSM_ESTOP → 长按 PC13 3s 才复位；
- ☐ **nFAULT 硬急停**：短接 AT8236 nFAULT 到 GND（模拟过流）→ 立刻进 ESTOP（不等主循环，ISR 直切）；
- ☐ **参数回退**：`RUN` 前固件自动快照；手动 `SET kp_angle 999` 后发 `ROLLBACK` → `GET kp_angle` 回到快照前的值；
- ☐ **回退不需 COMMIT**：`ROLLBACK` 只恢复 RAM，**Flash 不动**（避免 20~40ms 擦除阻塞）；若需永久回退才手动 `COMMIT`。

**其他验收**：
- ☐ **Flash 擦写次数**：连续 `COMMIT` **1000 次** → Flash 主页 CRC 仍正确（乒乓策略生效，write_count 交替上升）；
- ☐ **控制拍不受影响**：在 `COMMIT` 进行中用示波器看 PA8（PWM），无中断（因为 COMMIT 在主循环里跑，SysTick 抢占正常）；
- ☐ **STAT 命令任何时候能回**（证明主循环没被卡住）。

- ☐ **C 阶段**：vmax 单调上升直到撞 `vmax_ceiling` 或 P95 门限，二分收敛；
- ☐ **回退**：手动制造失败（`SET vmax 9999`）→ 调参器能 `ROLLBACK` 到 `last_good`；
- ☐ **实车噪声实测**（使用手册 §8 缺口）：**同一组参数连跑 6 圈量波动** → 定 `accept_eps` 与 `lap_per_config` 的真值；
- ☐ **M6 临界点问题**（使用手册 §8 缺口）：验证 C 阶段在临界速度附近是否"达标/不达标"来回翻；若是 → 拍板选修法（升速只接受有裕度的档 / 要求连续 2 次达标）。

## 9. 待你拍板（**不超过 5 条**）

以下 5 条是军师拿不准的、需你定的：

1. **工程根目录名字**：建议 **`c:\Users\asus\Desktop\test16\bcar\`**（与 `固件-STM32空壳\` 并列）。或你愿意叫 **`bcar-fw\`** / **`b_car\`** / 其他？（一旦定了就不改，避免 Keil 重新生成工程时路径断）

2. **参数区落盘策略**：本框架提的 **Flash 末页乒乓双备份 + CRC32**（需 COMMIT 才落盘，2 万次寿命）。另一选择是 **每次 SET 立刻落盘**（方便，但每天调参 100 次就只够用 200 天，且每次 SET 多 20~40ms 擦除阻塞）。选哪个？（推荐：乒乓 + 手动 COMMIT）

3. **阶段 8 前要不要先做一个"最小可用固件"（阶段 1~5 合一个 hex）**？即先把 LED+串口+电机开环+编码器+IMU+灰度全打通，不跑完整循迹，先给一个能接调参迭代器 `--phase A` 诊断的版本？还是一次性把阶段 0~8 全走完才交？（推荐：先交阶段 1~5 的中间版，能早一点验证"串口双向通"这个历史悬案）

4. **nav_path.h 赛道几何表谁出初值**？军师可以从赛道图（`文档\赛道图-5000x5000-黑底白线.png`）与 `赛道情报-黑底白线5m-20261002.md` 里提取坐标，产出 96 段 `{s, x, y, yaw, R}` 初值（【算术】+【猜的】）；或你先实地量赛道后才给？（推荐：军师先出初值，阶段 7 实跑时工人修正）

5. **P² 分位近似算法要不要现在实现**？一个选择是先写简单版（环形缓冲 256 拍，只算最近 1.28s 的 P95），阶段 8 先能跑；之后如果调参器对 P95 语义敏感（必须整圈）再升级到 P²。另一选择是一步到位 P²（多花半天）。选哪个？（推荐：先环形缓冲简版，阶段 9 发现不够用再升 P²——因为 v1.9 P95 门限本身也是整数级，精度要求不高）
