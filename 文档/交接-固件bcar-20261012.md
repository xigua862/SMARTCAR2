## 5. ★五条硬纪律（接手必看，全是踩出来的）

1. **新源码一律放 `bcar\src\`**（`src/bsp` / `src/drivers` / `src/middleware` / `src/app`）。
   *为什么*：Windows 不区分大小写，工程根目录的 `drivers/` 会和 CubeMX 的 `Drivers/`（HAL 库）
   **撞成同一个目录**，CubeMX 重新生成时 `DeletePrevious=true` 会把我们写的驱动一起删掉。
2. **改完源码先跑 `python Tools\fix_bom.py`**。
   *为什么*：中文 Windows 下 ARMCC 按 GBK 解析，UTF-8 源码里的中文会被判非法（`#870-D`），
   一堆 warning 会破坏"0 warning"判据。加 BOM 后正常（二进制里仍是 UTF-8，串口显示中文没问题）。
3. **CubeMX 重新生成工程后跑 `python Tools\patch_uvprojx.py`**。
   *为什么*：CubeMX 只列它自己生成的文件，我们 `src/` 下的会被挤出 Keil 工程。
   脚本幂等（先删旧组再按磁盘重建），跑几次都行。
4. **外设初始化手写在驱动里**（USART1 / TIM1 / TIM2 / TIM3 / ADC1 都是），不走 CubeMX 生成。
   *为什么*：重映射、MOE、编码器 4 倍频这些 CubeMX 命令行搞不定（实测 `IP not ready`）；
   手写还有个好处：意图在明面上，重新生成工程也不会被改回去。
5. **`middleware/` 不许 include 任何 stm32/HAL/驱动头文件**。
   *为什么*：这样才能在电脑上用 gcc 直接编译单测。要加可测算法 → 放 `middleware/`
   并在 `Tools\run_pc_tests.py` 里注册一行。

## 9. 几个关键设计决定（为什么这么做）

1. **5ms 主循环 + SysTick 置标志**：ISR 里只 `tick++` 和搬字节，业务全在主循环。
   避免 ISR 里跑算法导致时长失控（框架 §3.2）。
2. **惯导为主 + 光电为辅**：航向用陀螺积分（**先减零偏、再过死区**），
   拿不到 DRDY 就退回"差速推算"——IMU 挂了车还能勉强跑，不会直接瘫。
3. **丢线拍不计入偏差统计**：丢线时 `err` 恒为 0，混进来会把指标做漂亮，
   而丢线恰恰是最危险的时候。这条专门写了单测卡住。
4. **用 P95 而不是 max 当收敛判据**：max 被单次反光/震动拉爆，调参器会一直追噪声；
   P95 才是"常态最坏情况"。
5. **遥测走 TX DMA**：见坑清单最后一条。
6. **灰度每路各自归一化**：8 个探头一致性差（发射管亮度/贴纸高度/反光都不同），
   用统一阈值必然有的永远亮、有的永远灭。
7. **`err_mm` 直接给毫米**：转向环拿它就能用，不用再标一层系数。
